Team guide

Online Library is a website where students find books, manga and manhwa, check if they are available, and read them online. This HTML is finished. The CSS team makes it look good and the JS team makes it work. Nobody needs to change the HTML except to fix mistakes. Tell the HTML person first, because the same change may be needed on every page.

Files you create

  • css/style.css: all styles, for the CSS team.
  • library/books.json: the list of books. The admin page writes it, so nobody edits it by hand.
  • js/app.js: code every page needs (login check, saving, toast, header changes).
  • js/home.js, catalog.js, book-details.js, reader.js, login.js, my-library.js, admin.js: one file for each page. The names match the HTML file names.

What a book looks like in library/books.json

The file is a list of books. Every book is an object like this one:

{
  "id": 1,
  "title": "Pride and Prejudice",
  "author": "Jane Austen",
  "genre": "Romance",          // chosen from the fixed genre list
  "type": "text",              // text, manga, manhwa or comic
  "year": 1813,
  "copies": 2,                 // how many copies the library owns
  "desc": "Short description in your own words.",
  "textFile": "library/text/1.txt"    // for type text
}

A series with chapters is still ONE book in the list. Its chapters sit inside it:

"chapters": [
  { "number": 1, "title": "The Bridge", "key": "c1", "folder": "library/pages/28/c1", "pageCount": 20, "ext": "webp", "pad": 4 },
  { "number": 2, "title": "Night Watch", "key": "c2", "folder": "library/pages/28/c2", "pageCount": 18, "ext": "webp", "pad": 4 }
]

Page images are named 0001.webp, 0002.webp and so on inside the chapter folder (pad is the number of digits, ext is the file type). The admin page creates this layout and uploads the files for you.

Use books that are free to share, such as the public-domain ones on gutenberg.org. Do not copy text from books that are still under copyright.

What gets saved in the browser (localStorage)

There is no server, so the browser's localStorage keeps the users and their reading lists, loans, waitlists and progress. The books themselves are saved in GitHub by the admin page. It only stores text, so turn objects into text with JSON.stringify and back with JSON.parse.

KeyWhat it holds
usersA list of users. Each user has username, password, role (user or admin), list, loans and waits (all book ids), and progress, which remembers where the user stopped: { 28: { ch: 2, page: 7 } }.
currentUserThe username of the person logged in, or nothing.

Saving books to GitHub

The admin page saves a book by committing its files to the website's GitHub repository, so every visitor sees it after the site republishes (usually within a minute or two). The admin needs a fine-grained GitHub token for that one repository with the permission Contents: Read and write. Keep the token private and never put it in the code.

PDFs are turned into page images with PDF.js (a free library from Mozilla). Put pdf.min.js and pdf.worker.min.js (version 3.11.174 from cdnjs.com) in a folder named lib to work offline, otherwise the page loads them from cdnjs.

How borrowing works

  1. Free copies = the book's copies minus the number of users who have it in loans.
  2. Free copies above zero: Borrow adds the book id to the user's loans.
  3. No free copies: Join the waitlist adds the book id to the user's waits.
  4. Return removes it from loans. If someone is waiting, move the book from their waits to their loans.

Testing

  • Open index.html in Chrome or Edge. Press F12 and open the Console tab to see JavaScript errors.
  • In the Application tab you can see and delete what is saved in localStorage.
  • Test as a guest, as a normal user and as admin / admin123.
  • Test on a phone-sized screen with the device toolbar (Ctrl+Shift+M).
